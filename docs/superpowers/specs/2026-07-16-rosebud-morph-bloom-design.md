# 玫瑰花苞 Morph 开花动画设计

## 目标与替代关系

本设计使用每片花瓣的 shape key / glTF morph target，让开放花瓣自身产生内卷和杯状曲率，从自然花苞连续展开为当前完整开放玫瑰。

本设计取代 `2026-07-16-natural-rosebud-bloom-design.md` 中仅依赖花瓣整体位移、缩放和小角度旋转的闭合方式。此前方案已通过浏览器截图与几何统计证明无法同时满足自然花苞外观、`8°` 旋转上限和穿插门禁。

## 已确认的视觉结果

- 起始姿态是自然花苞：外圈略微张开，中圈形成包裹层，中心花瓣紧密内卷，不露出成熟玫瑰的开放螺旋。
- 花瓣从外圈到内圈依次展开，变化来自花瓣曲率逐渐恢复，而不是整体花头等比放大。
- 过程中不得出现碎片状尖角、突然翻面、明显闪烁或硬切换模型的感觉。
- 最终开放姿态、材质、花茎、叶片、灯光、相机、粒子和交互保持不变。

## 方案选择

采用程序化生成的逐花瓣 shape key。每个 `Petal_*` 保留当前开放几何作为 `Basis`，并生成一个 `Bud` 形态。运行时只动画 `Bud` 权重，不使用独立花苞模型，也不依赖大角度刚体旋转。

没有采用 Lattice 烘焙方案，因为 25 个独立控制器会增加脚本复杂度和重复生成风险；没有采用手工雕刻方案，因为它难以自动复现和维护。

## 花瓣形变模型

### 局部坐标

对每片花瓣计算：

- 根部锚点 `O`：沿用现有花瓣最低 `12%` 顶点带的平均位置。
- 花瓣生长方向 `G`：从根部锚点指向花瓣开放姿态质心。
- 向花心方向 `R`：从根部锚点指向花朵水平中心。
- 弯曲轴 `T`：由 `G` 与 `R` 构造的切向轴；退化时使用与 `G` 正交的稳定备用轴。

每个顶点根据其沿 `G` 的投影得到 `t ∈ [0, 1]`。根部保护区 `t ≤ 0.15` 不移动；保护区之后使用平滑曲线计算形变量，越靠近尖端，内卷越强。

### Bud 目标形态

`Bud` 顶点由三种连续形变组合产生：

1. 围绕 `T` 的渐进弯曲，使花瓣尖端向花心和上方内卷。
2. 随 `t` 增强的径向收拢，使中内圈形成杯状包裹层。
3. 轻微的切向错位，避免所有花瓣尖端汇聚到同一点，保留玫瑰交错层次。

同一物理花瓣已经聚合的正面、背面和侧边使用完全相同的连续顶点变换，因此不会重新出现三层网格各自运动造成的碎片感。

形变强度按层递增：

- 外圈：轻度弯曲，保留少量张开轮廓。
- 中圈：中度弯曲和径向收拢，形成花苞主体。
- 内圈：强度最高，尖端内卷并覆盖中心。

经分量隔离诊断，原始弯曲范围会造成过量表面交叉；最终采用外圈 `3°`、中圈 `6°`、内圈 `11°` 的顶点渐进弯曲。径向收拢负责花苞聚合，较小的非刚体弯曲负责花瓣尖端内卷；花瓣对象变换保持开放姿态不变。

## 动画与导出

- 每片花瓣包含 `Basis` 和一个 `Bud` shape key。
- 起始和该层开始展开前，`Bud` 权重保持 `1`。
- 展开过程中权重使用平滑缓动从 `1 → 0`。
- 外圈最先展开，中圈随后，内圈最后；保留现有约 `4.5s` 的 glTF 动画时长与最终停留行为。
- `RoseBloom` 只允许 morph `weights` 通道；花瓣对象不生成 translation、rotation 或 scale 动画，所有闭合形变都写入 `Bud` 目标。
- 最终帧所有 `Bud` 权重精确为 `0`，因此 `Basis` 即当前开放模型，开放姿态不受形变算法影响。
- `src/model/rose.glb` 与 `public/models/rose.glb` 仍由同一次导出产生并保持字节一致。

## 生成流程与幂等性

1. 导入当前 GLB，并在最终开放帧读取开放姿态。
2. 清除旧动画；若模型已有 `Bud` morph target，保留开放 `Basis` 后删除旧目标，避免重复叠加形变。
3. 继续使用现有逻辑识别并聚合为 25 个完整物理花瓣，计算外、中、内三层。
4. 为每片花瓣生成一个 `Bud` shape key，并写入 `RoseLayer` 元数据。
5. 创建按层错峰的 `RoseBloom` 权重动画，导出并复制两份 GLB。
6. 第二次从已生成 GLB 运行脚本时，仍应得到 25 个花瓣、每片一个 `Bud` 目标和相同的开放终态，不得累积旧形变。

## 安全约束与错误处理

- 每片花瓣的顶点数和拓扑在 `Basis` 与 `Bud` 之间必须完全一致。
- 根部保护区顶点位移不得超过 `1e-5`，避免花瓣与花托脱离。
- 生长方向、向心方向或弯曲轴无法稳定计算时，生成脚本必须失败并指出花瓣名称，不能静默导出异常模型。
- 禁止生成花瓣 rotation 动画；花瓣对象相对开放姿态的旋转保持 `0°`。
- 最终开放边界与当前开放模型的差异继续限制在 `1e-4`。
- 若某片花瓣的形变导致明显翻面或穿插，调整该层的顶点弯曲/收拢强度，而不是恢复大角度刚体旋转。
- 若动画或 morph target 加载失败，前端沿用现有降级行为，显示完整开放姿态。

## 验证标准

### 自动验证

- `RoseBloom` 恰好动画 25 个 `Petal_*` 节点，每个节点有且仅有一个 morph target 和一个 `weights` 动画通道。
- 动画起始权重为 `1`，最终权重为 `0`，时长保持 `4.0–5.0s`。
- 不存在花瓣 rotation 动画通道，最终开放边界保持 `1e-4` 容差。
- 根部保护区、顶点数量、有限数值、目标位移和 GLB 两份副本一致性均通过检查。
- Blender 逐帧 BVH 采样继续执行；任一采样帧不得超过 `80` 组相交花瓣或 `40,000` 组三角面重叠，不能通过放宽门禁掩盖碎片或翻面。

### 浏览器视觉验证

- 全新会话首次出现的玫瑰必须读作花苞，而不是缩小的半开花。
- 首帧外圈略开、中圈包裹、中心紧闭，不能看到成熟花的开放螺旋。
- 连续截图确认从外到内展开，轮廓连续，无碎片、跳变或换模型感。
- 最终帧与当前开放玫瑰一致。
- 关闭并重新打开后，必须再次从同一个合格花苞开始。

## 文件边界

- `scripts/prepare_rose_bloom.py`：生成 `Bud` shape key、权重动画和 GLB。
- `scripts/verify-rose-glb.mjs`：验证 morph target 与权重动画合同。
- `scripts/verify_rose_bloom_geometry.py`：验证逐帧世界空间几何、对象旋转为零和最终姿态。
- `src/model/rose.glb`、`public/models/rose.glb`：生成资产。
- `src/lib/rose-animation.ts`、`scripts/check-rose-animation.ts`：最终模型缓存键。
- 前端播放器接口和 `ThreeRose.tsx` 不改动。

## 不在本次范围

- 独立花苞模型或花苞与开放模型之间的交叉淡化。
- 手工逐片雕刻或需要 Blender GUI 人工维护的控制器。
- 新增多个 morph 表情、风摆、闭花循环或花茎叶片动画。
- 修改开放玫瑰的最终造型或现有展示时序。
